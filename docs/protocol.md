# Technics EAH-AZ80 制御プロトコル（RACE）

公式 Android アプリ「Technics Audio Connect 5.0.1」の解析と、実機（ファームウェア `JNQ1ZI 1.035`）での確認結果。
「実機」列の値は 2026-10-29 に PC から読み取ったもの。

## 経路

- Classic Bluetooth の RFCOMM（SPP）。サービス UUID `00000000-0000-0000-0099-AABBCCDDEEFF`（Airoha の RACE）。
- チップは Airoha AB156x（SDK `IoT_SDK_for_BT_Audio_V2.9.0.ULL_TWS_Headset`）。Bluetooth Device ID のベンダー `0x0094` = Airoha。
- 音楽再生中でも接続できる。**同時に 1 台しか接続できない**（スマホの公式アプリが接続中だと WSAError 10064）。

## パケット

```
要求: 05 5A <len:LE16 = payload長+2> <id:LE16> <payload>
応答: 05 5B <len> <id> <status> <値…>      status 0 = 成功
通知: 05 5D <len> <id> …
```

- 公式アプリの解析コードは、パケット全体での位置で値を読む（[6] = status、[7] 以降 = 値）。`RacePacket.At(index)` は同じ数え方。
- 一部のコマンドは「応答（5B）で受付 → 通知（5D）で値」の 2 段階（`RaceReply.Indication`）。

## 相方（左右）

| ID | 内容 |
|---|---|
| `0x0D00` | 中継先の一覧。応答はステータスなしで `(種別, ID)` の組が並ぶ。実機 `05 06`（種別 0x05 = 相方） |
| `0x0D01` | 中継。payload = `[種別, ID] + 内側のパケット全体`。応答は受付 5B のあと、5D の中に相方側の応答パケットが入る |
| `0x0CD4` | 主側が右か。実機 `00`（主側 = 左） |

- 公式アプリは外音コントロールなどを**主側に 1 回だけ**送る。相方へはファームウェアが反映する（実機で確認: 主側への `0x000B` の直後に、中継で読んだ相方の値も変わっていた）。
- 相方へ中継で設定（`0x0D01` で `0x000B` を包む）も受け付けられる（status 0）。アプリでは左右が揃わないときの最終手段として使う。

### 左右の設定と音のずれ（調査メモ）

- アプリが書き込むのは主側だけ（公式アプリと同じ）。相方へ直接書くのは、主側への再送でも左右が揃わなかったときの最終手段（中継設定）だけで、
  そのときも主側と同じ値を送る。左右に別々の値を書く経路はない（キー割り当ては左右で別々に持つ設定なので対象外）。
- 外音コントロール・アンビエントモード・サウンドモード・NC の最適化・切り替え順は、画面から送ったときに左右を読んで一致を確かめる。
  それ以外（接続モード、マルチポイント、装着検知、オートパワーオフ、タッチ操作、LED、通話のノイズ抑制）は公式アプリと同じく
  主側に送るだけで、左右の比較は接続したときに一度だけ行う（`TechnicsDevice.CompareSettingsAsync`。`technics dump` でも確認できる）。
- 定期の読み直しは主側だけ読む。相方の外音コントロールまで読んで比べるのは、接続直後・イヤホンのタッチ操作のあと・相方がつながり直したときだけ。
  相方がつながっているかは `0x0D00`（主側だけで答える）で確かめる。
- 設定やタッチ操作の直後は、相方への反映待ちで一瞬だけ左右がずれて読めることがある。1 回読み直してから不一致と判断する。
- アプリは音声（A2DP）には触れない。再生・一時停止で左右の音の出だしがずれるかは、アプリを終了した状態（トレイの「終了」）でも
  同じか比べて切り分ける。アプリの通信は RFCOMM の小さな要求だけで、ウィンドウを閉じているあいだは 60 秒に 1 回に減らしている。

## Airoha 標準

| ID | 内容 | 実機 |
|---|---|---|
| `0x0301` | SDK 版 | `IoT_SDK_for_BT_Audio_V2.9.0.ULL_TWS_Headset` |
| `0x1E08` | ビルド情報 | `ab156x_evb`、2024/04/10 |
| `0x0CD6` + `[左右]` | 電池。通知 `左右, %` | 左 70%、右 72% |
| `0x1C07` + `[左右]` | ファームウェア版。通知 `左右, 長さ, ASCII` | `JNQ1ZI 1.035` |

## イヤホンからの通知

- `0x000A` の 5D: タッチ操作などで外音コントロールが変わった。[7]=mode, [8]=NC の強さ, [9]=外音の強さ。

## 送らないコマンド

`RaceWhitelist` で遮断している。FOTA（`0x1Cxx`、ただし `0x1C07` は除く）、Flash／Storage（`0x04xx`、`0x07xx`）、NVKey 書き込み（`0x0Axx`）、
リセット（`0x1C05`）、Panasonic の `0x0001`（機種 ID 書き込み）、`0x0003`（本体色書き込み）、`0x0041`（初期化）、`0x0042`（電源 OFF）、
`0x004B`（デモモード）、`0x0054`（充電エラー解除）、`0x006B`（ペアリング開始）。

## AZ80 で応答しないコマンド

`0x005B`、`0x0055`、`0x0057`、`0x0059`、`0x005C`、`0x0063`、`0x0066`、`0x0067`、`0x006C`、`0x0074`、`0x0076`。

## 解析ツール

`tools/analysis/` の Python スクリプト（標準ライブラリのみ。`python -I` で実行）。

- `race_probe.py <アドレス> <ID[:payload]>...`: RACE を直接送って応答を表示する（読み取り専用の確認用）。
- `dexdump.py`、`dis.py`: dex の定数と Dalvik バイトコードを読む。
- `arsc.py`、`axml.py`: `resources.arsc` とバイナリ XML を読む（画像名と難読化されたファイル名の対応、画面構成）。
